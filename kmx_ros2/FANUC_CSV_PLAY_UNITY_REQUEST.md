# FANUC CSV再生（方式A）— Unity(KMX)側 実装要望書

ROS/FANUC 側担当（a-tanaka）→ **Unity(KMX) 担当** への要望。
KMX が計画した経路を、FANUC 側の**固定プログラム**（`KMX_LOAD`(Karel)＋`KMX_PLAY`(TP)）が **CSV(関節角) を読んで再生**する方式A。
**ROS/FANUC 側は実装・実機(ROBOGUIDE)でE2E動作確認済み（2026-07-17）**。残りは Unity 側の「CSV生成＋正しい場所・名前で配置」。

---

## 0. 動作確認済みの全体像
```
KMX(Unity) 経路計画 → CSV(関節角)生成 → 配置(フォルダ/FTP/USB)
     → [FANUC] R[89]=品番, R[88]=パス番号 設定 → KMX_PLAY 実行
        → KMX_LOAD が UD1:\KMX\P<品番>_<パス番号>.CSV を読み PR[1..count] 充填
        → KMX_PLAY が J PR[1..count] で再生（ロボットが KMX プレビューと同じ経路をなぞる）
```
検証済み：品番=1 の 100点CSV を `UD1:\KMX\` に置き、KMX_PLAY で100点再生成功。

---

## 1. ★CSVファイル名 ＝ 品番 ＋ パス番号（要対応）

**`P<品番>_<パス番号>.CSV`**（例：品番1234・パス2 → `P1234_2.CSV`）

| 項目 | 内容 |
|---|---|
| 品番 | 整数。FANUC レジスタ **R[89]** と一致させる |
| パス番号 | 整数。FANUC レジスタ **R[88]** と一致させる |
| **パス番号 0** | **＝復帰動作**（復帰モードの経路）。例 `P1234_0.CSV` |
| パス番号 1以上 | ＝登録経路（登録モードの経路）。例 `P1234_1.CSV`, `P1234_2.CSV` … |

- パス番号は**0も必ずファイル名に含める**（0＝復帰の意味を持つため省略しない）。
- 品番・パス番号は**整数**（ファイル名に使うので符号・空白・小数を入れない）。
- KMX_LOAD は `R[89]`(品番)・`R[88]`(パス番号) から上記名を組み立てて読む（実装済み）。

---

## 2. ★出力先フォルダ ＝ プロジェクト（ワークセル）ごとに変わる → **設定項目にする**

FANUC 側は常に `UD1:\KMX\` を読む。Unity 側は環境に応じて「そこに対応するホスト側の場所」へ書く。

### (A) ROBOGUIDE（机上・現状の開発環境）
書き込み先（＝ROBOGUIDE の `UD1:` 実体）:
```
<ワークセルルート>\Robot_1\UD1\KMX\P<品番>_<パス番号>.CSV
```
- 現環境の例：
  `C:\Users\gi-guest\Documents\My Workcells\KmxTest\Robot_1\UD1\KMX\P1234_2.CSV`
- **`<ワークセルルート>`（`...\My Workcells\<セル名>\`）はプロジェクト/PCで変わる** →
  **KMX の設定（ini/ScriptableObject 等）で指定できるようにする。ハードコード禁止。**
- サブフォルダ `KMX` が無ければ作成する。

### (B) 実機（本番）
`UD1:\KMX\` へ届ける。どちらでも可：
- **FTP**（推奨）：FANUC の FTP サーバへ put（`UD1:\KMX\P<品番>_<パス番号>.CSV`）。KMX から自動転送。
- **USB**：`P<品番>_<パス番号>.CSV` を入れた USB を UD1 ポートに挿す。

→ **KMX_LOAD 側は (A)(B) 共通で `UD1:\KMX\...` を読む**。Unity 側は「置き場所（フォルダ or FTP or USB）」だけ環境で切替。設定で **モード(ROBOGUIDE/実機FTP/USB)＋接続先** を選べると理想。

## 3. CSV フォーマット（確定・KMX_LOAD 検証済み）

```
count,group,uframe,utool,speed,cnt        ← 1行目：整数6
J1,J2,J3,J4,J5,J6                          ← 2行目〜：度・小数（点数=count 行）
J1,J2,J3,J4,J5,J6
...
```

| フィールド | 意味 | 例 | FANUC出力先 |
|---|---|---|---|
| count | 点数 | 100 | R[90] |
| group | モーショングループ | 1 | R[91] |
| uframe | UFRAME番号 | 0 | R[92] |
| utool | UTOOL番号 | 1 | R[93] |
| speed | 速度(%) | 100 | R[94] |
| cnt | CNT値(0-100) | 100 | R[95] |
| J1..J6 | 各点の関節角(度) | 0.0,40.0,... | PR[1..count] |

- **ASCII・カンマ区切り・コメント無し**。改行は **CRLF/LF どちらでも可**（KMX_LOAD はカンマ/空白/改行すべてを区切りとして数値を順に読む）。
- **★J3 は J2 換算済みの値**（`FanucLsExporter` と同じ規約＝FANUC の J3 に直接入る値）。KMX_LOAD は換算しない（そのまま PR へ）。
- **count ≤ `$MAXPREGNUM`（既定100）**。100超は将来 Phase2（Karel↔TP バッチ）。当面は ≤100 で。
- 既に `FanucCsvExporter` があるとのことなので、上記命名・配置先の対応が主な追加分。

## 4. 実行フロー / タイミング

1. KMX が「品番＋パス番号」の経路を計画（登録=パス1以上／復帰=パス0）。
2. KMX が `FanucCsvExporter` で CSV を生成し、**§2 の場所へ §1 の名前で書く**（or FTP push）。
3. 生産側（PLC/PNS or 手動）が **R[89]=品番, R[88]=パス番号** を設定。
4. `KMX_PLAY` 実行 → KMX_LOAD が該当CSVを読み PR 充填 → 再生。

- **R[89]/R[88] を誰が設定するか**は運用次第（上位PLC/PNS／KMX が ROS 経由／手動）。少なくとも「Unity が生成する CSV 名」と「実行時に設定される R[89]/R[88]」が一致していれば動く。
- 同じ品番で複数パス（0=復帰,1,2,…）を用意しておき、パス番号だけ変えて `KMX_PLAY` を使い回す（プログラム再生成不要）。

---

## 5. 注意点

- **フォルダパスは環境依存 → 設定化必須**（§2）。配布時にワークセル名/ドライブが変わる。
- **ROBOGUIDE のキャッシュ**：稼働中に上書きしたファイルが稀に即認識されないことがある（起動時読込のため）。実機では即読める。今回の検証では上書きで読めた。気になる場合はコントローラ再起動 or MENU>FILE で確認。
- 品番・パス番号は**整数**（ファイル名に直結）。
- CSV は KMX_LOAD が「カンマ/空白/改行」を区切りに読むので区切りに神経質でなくてよいが、**数値以外の余計な文字（単位記号・引用符等）は入れない**こと。

## 6. 分担まとめ

| 側 | 担当 |
|---|---|
| **Unity(KMX)** | CSV生成(`FanucCsvExporter`)／**出力先フォルダの設定化**（ROBOGUIDE/実機FTP/USB）／**命名 `P<品番>_<パス番号>.CSV`**（パス0=復帰）／FTP or フォルダ書込 or USB |
| **ROS/FANUC** | `KMX_LOAD`(CSV→PR・品番+パス番号対応・**実装/実機確認済**)／`KMX_PLAY`(再生)／レジスタ規約 |

## 7. FANUC 側レジスタ規約（参考）

| R[] | 向き | 意味 |
|---|---|---|
| **R[89]** | in | **品番** |
| **R[88]** | in | **パス番号**（0=復帰動作 / 1以上=登録経路） |
| R[90..95] | out | count, group, uframe, utool, speed, cnt |
| R[96] | out | 1=成功 / -1=失敗 |
| R[97..99] | out | 診断（OPEN状態/READ状態/デバイス番号） |
| PR[1..count] | out | 各点の関節位置（`SET_JPOS_REG`） |

以上。ご不明点あれば ROS/FANUC 側（a-tanaka）まで。
