# 新しい製番を作る流れ（ボタン一つ）引継ぎ

2026-11-09 時点。KMX（Unity 側）と KMXTool 側の両方ができた。7763（S1820）で一度通した。そのあと足した変更（作成用シーン・プロジェクト名・タグの初期値・プレハブのロード・Unity を開いたままでの実行・起動用ランチャー）は、まだ通していない。

## 目的とユーザーの決定

新しい製番を作るときの次の手作業を、KMXTool のボタン一つにする。

1. SolidWorks のデータをプレハブに変換する（Pixyz）
2. Addressables を作る
3. KMXTool でその製番の設定を作る
4. MMS Setting で DB と通信を設定する
5. パラメータを送信する（設定ファイル出力）
6. 実行ファイルを作る

決まったこと（ユーザー）：

- メニューは KMXTool の「ファイル」→「初期プロジェクト作成(&I)...」。
- ボタンは一つ。ユニット・動作・IO の設定は、出力したあとに人が KMXTool で行う。
- 通信の既定は**内部シミュレーション**（`PostgresSetting.innerMode = true`）。MMS Setting は使わない。配列モードは常に true（`MechSetting.isTagArray = true`）。
- タグの初期値は R8790 の 3 つ（機構位置・PLC X1・PLC Y1）。`MechSetting.CreateDefaultTags()`。ツリーで機番を新しく足したときも同じ物を入れる。
- 出てくる物は、**実行環境**と**その製番の KMXTool プロジェクト**。
- プロジェクト名は「製番 製番名」。
- 取込元は 3 通り。
  1. フォルダを指定して変換（既存の「Create Prefab Files」と同じ）
  2. ファイル（.sldasm）を指定して変換（同上）
  3. 作成済みのプレハブを選ぶ（複数選択）。変換は省く。プレハブは Unity プロジェクトの Assets の中にあること。
  - 1・2 は Pixyz のライセンスがある PC でだけ出す（`%LOCALAPPDATA%\Unity\licenses\UnityEntitlementLicense.xml` に Pixyz があるか）。
- 年度と製番を入れて「社内サーバーから取得」を押すと、機番と製番名を KIDS（Oracle）から取る（KIBTool と同じ SQL。`Common/KidsAccess.cs`）。
- Unity プロジェクト（常に KMX）とエディタは自動で探す。見つかれば画面に出さない。

## 出力の形

```
<作る場所>\<製番 製番名>\
  <製番 製番名>.json        … KMXTool のプロジェクト（プレハブはロード済み）
  Prefab\                   … プレハブと Addressables（Library\com.unity.addressables\aa\<製番> の中身）
  <機番>_<製番名>\KMX.exe   … 実行環境（KMX_Data\ServerData\<製番> に Addressables を入れる）
```

## KMX（Unity 側）

- `Assets/Scripts/Editor/KmxNewProdPipeline.cs`：流れの本体。`RunFromCommandLine`
- `PrefabImporter.ImportForPipeline(source, done)`：画面を出さずに変換する。**`DEV_PC` が有効なときだけコンパイルされる**（開発 PC では未コンパイル）。
- `AddressablePrefabRegistrar.RegisterForPipeline(folders, prefabs, 製番, done)`：画面を出さずに登録とビルドを行う。
- `BuildAndRun.BuildForPipeline(outDir)`：Windows の実行ファイルを `outDir` に作る。失敗したら例外。
- ビルドの前に、シーン（`Assets/Scenes/Simuration.unity`）を作成用シーン `Assets/Scenes/SimurationBuild.unity` にコピーし（追加で開く）、その中の機械のプレハブを入れ替えてビルドする。一番上にある物のうち、`Assets/3DModels` から来た物と、元のプレハブが無くなった物を消し、この製番のプレハブを名前そのままで入れる（実行時はシーンにある同じ名前のプレハブを使うため）。部屋のモデル等は残す。作ったあと（失敗しても）作成用シーンは消す。Simuration は触らない。終わったとき（Unity を閉じる場合）は Simuration を開いておく。
- Windows 版を作ると、`Tools/KMXLauncher.exe`（起動用ランチャー）を `KMX.exe` の横にコピーする（`BuildAndRun.CopyLauncher`）。ソースは `Tools/KMXLauncher`、作り直しは `dotnet build -c Release`。

### Unity の起動と KMXTool とのやり取り

```
Unity.exe -projectPath <KMX> -executeMethod KmxNewProdPipeline.RunFromCommandLine -kmxWork <作業フォルダ> -logFile <作業フォルダ>\editor.log
```

- `-batchmode` は付けない。起動時の Industry Toolkit の 401 を「Continue」で進めるため（ユーザーが 1 回押す）。
- 同じプロジェクトを Unity で開いているときは、新しく起動せず、開いている Unity に頼む（`Assets/Scripts/Editor/KmxToolBridge.cs`）。
  - Unity は `<プロジェクト>/Temp/KmxTool` に `alive.txt`（1 秒ごとに書き直す）と `busy.txt`（実行中だけ）を置く。KMXTool は `alive.txt` が 15 秒以内に書かれていれば開いていると見る（`Setting/UnityBridge.cs`）。
  - KMXTool はそこへ `request.json`（`kind`: newprod / lineart、`workDir`、線画は `mechId`・`outDir`・`width`）を置く。Unity は読んで消し、作業フォルダで上と同じやり取りをする。終わっても Unity は閉じない。
  - 再生中・実行中・コンパイル中は受け付けない（KMXTool の入力画面で止める）。開いているかどうかは `Temp\UnityLockfile` を排他で開けるかで調べる。

| ファイル | 向き | 中身 |
|---|---|---|
| request.json | KMXTool → Unity | `mode`（folder / file / prefabs）、`source`、`prefabs`（絶対パスの一覧）、`prodNo` |
| unity.log | Unity → KMXTool | 進み具合（1 行ずつ追記） |
| stage1.json | Unity → KMXTool | `ok`、`error`、`prodNo`、`aaDir`、`prefabs`（プレハブ名） |
| go.json | KMXTool → Unity | `ok`（false ならビルドせずに終わる）、`buildDir` |
| stage2.json | Unity → KMXTool | `ok`、`error`、`exeDir` |

- Unity は stage1 を書いたあと、go.json を最大 60 分待つ。失敗したら stage ファイルに `ok: false` を書き、終了コード 1 で終わる。

## KMXTool 側（ブランチ refine-AllSetting）

- `Componet/DlgNewProd.cs`：入力画面（取込元・年度・製番・機番・製番名・作る場所・進み具合）。作る前に、プレハブが Assets の中か、同名フォルダが無いか、Unity を開いていないか等を調べる。
- `Setting/NewProdPipeline.cs`：流れ。
  1. request.json を書いて Unity を起動し、stage1 を待つ。
  2. `aaDir` を `Prefab\` へコピーする。
  3. プロジェクトを組み立て（内部シミュレーション・配列モード・タグの初期値）、プレハブを読み込んで（「ファイルをロード」と同じ）保存する。
  4. 設定を Unity の `StreamingAssets\Datas` へ出力する。この間は `Properties.Settings.Default.isPrefab` を false にする（true だと Unity の `Assets\Resources\Pixyz` を書き換えるため）。`AppDefine.OutputSettingFile(setting, dirs)` で出力先を渡す。
  5. go.json を書き、stage2 を待つ。
  6. `Prefab\Addressables` を `<exeDir>\KMX_Data\ServerData\<製番>\` へコピーし、`saveDir2 = exeDir` にして保存し直す。
  7. 途中で失敗したら go.json に `ok: false` を書く。止めたら Unity を終わらせる。
- `Common/KidsAccess.cs`：KIDS から年度・製番で機番・製番名を取る。プロバイダは OraOLEDB.Oracle（64 ビットで MSDAORA は使えない）。`System.Data.OleDb` 9.0.0 を参照に足した。
- 「ファイル」の画面（`CmpPrmDxfFiles`）：「ファイルをロードしますか？」は、ファイルが変わったか、まだロードしていない・ロード後に更新されたファイルがあるときだけ聞く（初期オフセットだけの変更では聞かない）。

## 線画ナビの書き出し（KMXTool から）

- 「プロジェクト」→「線画ナビの書き出し(&L)...」（`Componet/DlgLineArt.cs`・`Setting/LineArtExport.cs`）。Unity を開いているときは、起動せずに開いている Unity に頼む（結果は作業フォルダの `result.json`、ログは `unity.log`）。
- Unity の `StreamingAssets\Datas` を控えてからこのプロジェクトの設定を出力し、Unity を `-executeMethod LineArtNavigationExporter.ExportFromCommandLine -lineArtMech <機番> -lineArtOut <出力先> -lineArtWidth 2000` で起動する。終わったら（失敗・中止でも）Datas を元に戻す。
- プレハブは Unity プロジェクトの Assets の中から名前で探すので、無ければ書き出す前に止める。

## アプリケーション書き出し（今の設定で実行環境を作り直す）

- 図面が更新されたときに使う。プロジェクトを右クリック →「アプリケーション書き出し...」（`Componet/DlgAppBuild.cs`・`NewProdPipeline.RunUpdateAsync`）。
- Pixyz のライセンスがあり Unity の `DEV_PC` が有効な PC：プレハブの一覧で「図面から変換し直す」に印を付けた物だけ、図面（.sldasm）から変換し直す。図面は「図面のフォルダ」（製番のフォルダ）の直下のフォルダからプレハブ名で探す。変換の出力先は図面の 2 つ上のフォルダ名で決まるので、図面のフォルダの名前が製番と違えば止める。
- ライセンスが無い PC：変換せず、Unity プロジェクトの Assets にあるプレハブ（設定で使っている物）をそのまま使う。
- 製番の初期値はプロジェクトの `Prefab\Addressables\ProdNo.txt`。出力先の初期値は、設定ファイル出力の出力先 2 から KMX.exe のある所（無ければプロジェクトの下に「機番_製番名」）。
- Unity には request.json の `mode = update`（`files` に変換し直す図面、`prefabs` にプレハブ全部）で頼む。あとは初期プロジェクト作成と同じ（stage1 → 設定の出力 → go → stage2）。
- 終わったら：変換し直したプレハブを、プロジェクトが読んでいるプレハブのファイルへ写す（ロードは人が行う）。プロジェクトに `Prefab\Addressables` があれば置き換える。実行環境の `KMX_Data\ServerData\製番` は消してから入れる。プロジェクトの設定は変えない。
- 作る前にリニアのポイント位置を検査し、問題があれば聞く（`Setting/LinearPointCheck.cs`。リニアの画面でも行に印を付け、保存のときに聞く）。

## 注意

- 初期プロジェクト作成で出力すると、Unity プロジェクトの `Assets\StreamingAssets\Datas` が新しい製番の内容になる（手で「設定ファイル出力」したときと同じ）。
- KMXTool の日本語ソースは UTF-8（BOM 付き）・CRLF。以前 Shift-JIS と取り違えて文字化けさせた事故がある。
- enum は JSON に数値で保存される。途中に足さない。
