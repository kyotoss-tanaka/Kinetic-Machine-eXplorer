# 新しい製番を作る流れ（ボタン一つ）引継ぎ

2026-11-07 時点。続きはライセンス（Pixyz）のある PC で行う。

## 目的とユーザーの決定

新しい製番を作るときの次の手作業を、KMXTool のボタン一つにする。

1. SolidWorks のデータをプレハブに変換する（Pixyz）
2. Addressables を作る
3. KMXTool でその製番の設定を作る
4. MMS Setting で DB と通信を設定する
5. パラメータを送信する（設定ファイル出力）
6. 実行ファイルを作る

決まったこと（ユーザー）：

- ライセンスのある PC で行う。
- ボタンは一つ。ユニット・動作・IO の設定は、出力したあとに人が KMXTool で行う。
- 通信の既定は**内部シミュレーション**（`PostgresSetting.innerMode = true`）。MMS Setting（外部の道具）は使わない。配列モードは常に true（`MechSetting.isTagArray = true`）。
- ボタンを押して出てくる物は、**実行環境**と**その製番の KMXTool プロジェクト**。
- 取込元は 3 通り。
  1. フォルダを指定して変換（既存の「Create Prefab Files」と同じ）
  2. ファイル（.sldasm）を指定して変換（同上）
  3. 作成済みのプレハブを選ぶ（複数選択）。変換は省く。プレハブは Unity プロジェクトの Assets の中にあること（Addressables に登録するため）。選ぶ画面は `Assets\3DModels` から開く。製番の初期値はプレハブのフォルダ名。複数のフォルダなら `G822_G823` のようにつなぐ（Multiple Folders と同じ）

## 出力の形（案）

```
<作る場所>\<製番>\
  <製番>.json            … KMXTool のプロジェクト
  Prefab\                … プレハブと Addressables（Library\com.unity.addressables\aa\<製番> の中身）
  <機番>_<機械名>\KMX.exe … 実行環境（KMX_Data\ServerData\<製番> に Addressables を入れる）
```

## できていること（KMX・Unity 側。コンパイル済み、動かしてはいない）

- `Assets/Scripts/Editor/KmxNewProdPipeline.cs`（新規）：流れの本体。`RunFromCommandLine`
- `PrefabImporter.ImportForPipeline(source, done)`：画面を出さずに変換し、終わったら `done(成功, 製番)`。
  - **`DEV_PC` が有効なときだけコンパイルされる**。このための変更はまだ一度もコンパイルしていない（開発 PC に Pixyz が無いため）。メニュー「Create Prefab Files」と同じ設定を写しただけ。
- `AddressablePrefabRegistrar.RegisterForPipeline(folders, prefabs, 製番, done)`：画面を出さずに登録とビルドを行い、`done(エラーの文。成功なら null)`。`prefabs` を渡すとそのプレハブだけを登録する。
- `BuildAndRun.BuildForPipeline(outDir)`：`BuildConfig.json` を使い、Windows の実行ファイルを `outDir` に作る。起動・ダイアログは出さない。
  - ビルドが失敗したら例外にした（以前は失敗しても「完了」と出ていた）。

### Unity の起動と KMXTool とのやり取り

起動の仕方：

```
Unity.exe -projectPath <KMX> -executeMethod KmxNewProdPipeline.RunFromCommandLine -kmxWork <作業フォルダ> -logFile <作業フォルダ>\editor.log
```

- `-batchmode` は付けない。起動時の Industry Toolkit の 401 を「Continue」で進めるため（ユーザーが 1 回押す）。Pixyz も画面ありで動かす。
- 同じプロジェクトを Unity で開いたままだと起動できない。`Temp\UnityLockfile` を排他で開けるかで調べる。

作業フォルダのファイルでやり取りする：

| ファイル | 向き | 中身 |
|---|---|---|
| request.json | KMXTool → Unity | `mode`（folder / file / prefabs）、`source`、`prefabs`（絶対パスの一覧）、`prodNo`（prefabs のとき） |
| unity.log | Unity → KMXTool | 進み具合（1 行ずつ追記） |
| stage1.json | Unity → KMXTool | `ok`、`error`、`prodNo`、`aaDir`（Library\…\aa\製番）、`prefabs`（プレハブ名） |
| go.json | KMXTool → Unity | `ok`（false ならビルドせずに終わる）、`buildDir`（実行ファイルの出力先） |
| stage2.json | Unity → KMXTool | `ok`、`error`、`exeDir` |

- Unity は stage1 を書いたあと、go.json を最大 60 分待つ。
- 失敗したときは、その段階の stage ファイルに `ok: false` とエラーの文を書き、終了コード 1 で終わる。
- ファイルは .tmp に書いてから置き換えるので、途中の内容が読まれることはない。

## 残り（KMXTool 側。C:\Users\…\source\repos\KMXTool、ブランチ refine-AllSetting）

1. **メニュー**：「ファイル」に「新しい製番を作る(&N)...」を足す。プロジェクト統合（`mniFileMerge`）の隣。終わったら `OpenProject(作ったjson)`。
2. **入力画面**（ダイアログ）：
   - 取込元の種類（3 通り）と取込元（フォルダ／.sldasm／プレハブの複数選択）
   - 製番。初期値は自動：フォルダ名、.sldasm なら 2 つ上のフォルダ名（Pixyz の変換と同じ決め方）、プレハブならフォルダ名
   - 機械名（BuildConfig の name。実行ファイルのフォルダ名 `<機番>_<機械名>` に使う）
   - 作る場所
   - Unity エディタ：`ProjectSettings\ProjectVersion.txt` の版から `C:\Program Files\Unity\Hub\Editor\<版>\Editor\Unity.exe` を探す。直せるようにして、Properties.Settings に覚える
   - Unity プロジェクト（KMX）：初期値は `strUnityDataPath`（`Kinetic Machine eXplorer.sln` があること）
   - 進み具合の欄
3. **流れ**（UI と分けたクラス。例：`Setting/NewProdPipeline.cs`）：
   1. 作業フォルダ（%TEMP%\KMXNewProd\日時）に request.json を書き、Unity を起動する。unity.log を表示し、stage1.json を待つ。stage1 より先に Unity が終わったら、editor.log の末尾を見せて止める。
   2. `aaDir` の中身を `<作る場所>\<製番>\Prefab\` へコピーする。
   3. プロジェクトを作る（`ProjectMerger` と同じく画面を使わずに組み立てる）：
      - `ProjectSetting { name = 製番, path = <作る場所>\<製番>\<製番>.json, user, dtSave }`
      - `postgresSettings = [ new PostgresSetting { innerMode = true, mechSettings = … } ]`
      - 機番はプレハブ名の最初の「-」の前（`R8790-A0-00-00` → `R8790`）。違う機番があれば機番ごとに `MechSetting` を作る。
      - `MechSetting { mechId, name = 機械名, isTagArray = true }`、`dxfFileSetting.prefabFiles` は `Prefab\<名前>.prefab`（プロジェクトからの相対パス）。
      - `prefabNodes` は空でよい（KMXTool で開いたときに読み直す）。
      - 保存は `ProjectMerger` と同じ `JsonSerializerOptions`（`Encoder = JavaScriptEncoder.Create(UnicodeRanges.All)`）。
   4. 設定を Unity プロジェクトへ出力する。
      - `AppDefine.OutputSettingFile` は出力先を `systemSetting.saveDirs`（`strUnityDataPath` と `saveDir2`）から決めるので、**出力先を渡せる形に分ける**。
      - **出力の間は `Properties.Settings.Default.isPrefab` を false にする**。true だと `KmxPrefab` が Unity の `Assets\Resources\Pixyz` にプレハブを写し、そこのほかのファイルを消すため。
   5. go.json（`ok: true`、`buildDir = <作る場所>\<製番>\<機番>_<機械名>`）を書き、stage2.json を待つ。
   6. `Prefab\Addressables` を `<exeDir>\KMX_Data\ServerData\<製番>\` へコピーする（`KmxPrefab.Output` の「Addressables 転送」と同じ形）。
   7. `systemSetting.saveDir2 = exeDir`（絶対パス。`saveDirs` は `Directory.Exists` で見るため）にして保存し直す。これで以降の「設定ファイル出力」が実行環境にも入る。
   8. 途中で失敗したら、go.json に `ok: false` を書いて Unity を終わらせる。
4. 注意：
   - 出力すると、Unity プロジェクトの `Assets\StreamingAssets\Datas` が新しい製番の内容になる（手で「設定ファイル出力」したときと同じ）。
   - KMXTool の日本語ソースは UTF-8（BOM 付き）・CRLF。以前 Shift-JIS と取り違えて文字化けさせた事故がある。
   - enum は JSON に数値で保存される。途中に足さない。

## ライセンスのある PC で確かめること

1. **`DEV_PC` を有効にする**：Player Settings の Scripting Define Symbols で `_DEV_PC` を `DEV_PC` にする。これはその PC だけの設定なので、コミットしない。
2. Unity でコンパイルが通るか（`PrefabImporter.cs` の変更が初めてコンパイルされる）。
3. まず取込元の 3（作成済みのプレハブ）で流れを通す。Pixyz を使わないので切り分けやすい。そのあと 1・2 を試す。
4. `-executeMethod` で起動したとき、401 の「Continue」のあと流れが進むか。Pixyz の変換が画面ありの起動で動くか。
5. できた KMX.exe が、内部シミュレーション・ユニットなしでモデルを表示するか。
