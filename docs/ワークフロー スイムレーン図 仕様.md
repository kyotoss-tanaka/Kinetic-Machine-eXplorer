# ワークフロー スイムレーン図 仕様

KMXTool の「ワーク図」を置き換える新しい表示の仕様。2026-09-05 合意。

図解版: https://claude.ai/code/artifact/cd3f7f49-182c-4315-94d4-1d82fb7a4bcc

---

## 目的

ワークが「どこで生まれ、何に持たれ、何に変わり、どこで消えるか」を1枚で追えるようにする。
現在のワーク図は工程を行・ワークを列に置いた表で、ワークの繋がりが線として表現されていない。

図として見えること以上に、**設定の整合性を機械的に検査できる**ことに価値がある。
順序が解けない・受け渡しに隙間がある、の2つはワーク落ちの直接原因になる。

## 決定事項

| 項目 | 決定 |
|---|---|
| レーンの単位 | **ワーク名**。実際に動かすケースとモデルを入れ替えるケースがあるが、まずはワーク名で始める |
| 既存ワーク図との関係 | **置き換える**。タブでの併存はしない |
| 横軸 | **工程順**と**サイクル内時間**の2モード |
| 同一タグの線 | 選択中のカードと同じタグだけ線を出す（常時全部は引かない） |
| 工程が未設定のとき | 使える形にする。ただし未設定の操作をどう並べるかは要検討 |
| 配色 | 現在のワーク図と同じ（生成=SeaGreen / 削除=IndianRed / アタッチ=SteelBlue / 変換=DarkOrange）。KMXの確認表示(Ctrl+Shift)とも一致 |

## 図の構成

- **レーン（行）** = ワーク。薄い帯がそのワークの存在期間
- **横軸** = 工程順、またはサイクル内時間
- **カード** = ワーク操作（生成・削除・アタッチ・変換）
- **オレンジの矢印** = 変換。変換元レーンから変換先レーンへ下りる
- **破線** = 同一タグ。選択中のカードと同じタグのみ

## 時間軸の元データ

`InnerProcess.json`（IOタイミング設定）が `tag` / `cycle` / `onTiming` / `offTiming` を持つ。
現案件（R0230）で確認した実測値:

| タグ | 名前 | ON | OFF | サイクル |
|---|---|---|---|---|
| `d_plc_y1[1034]` | 集積ヘッド下吸盤 | 700 | 2300 | 10800 |
| `d_plc_y1[896]` | シート取出し吸盤 | 5350 | 7600 | 10800 |
| `d_plc_y1[771]` | W吸盤1 | 7500 | 9000 | 10800 |
| `d_plc_y1[800]` | L吸盤2 | 8900 | **800** | 10800 |

`L吸盤2` は OFF < ON で、すでにサイクルをまたいでいる。

## サイクル番号の決定（制約充足）

各操作にサイクル内時刻 `t`（0〜サイクル長）が与えられる。
整数のサイクル番号 `k` を割り当て、絶対時刻 `T = t + k × サイクル長` が
すべての制約辺で増加するようにする。

### 制約（すべて設定から自動で導ける）

| 制約 | 由来 |
|---|---|
| 生成 < すべての操作 < 削除 | ワークの一生 |
| アタッチ ON < OFF | 保持の開始と解放 |
| 同一ワークの操作は工程順 | ユニットに割り当てた工程 |
| 変換元の変換 < 変換先の存在開始 | 変換先ワーク名が設定にあるので自動で辿れる |
| 合流点は両ワークで同一時刻 | 同一タグで複数ワークが動く点 |

### 解き方

トポロジカル順に走査し「**時刻が前より戻ったら k を1つ増やす**」だけ。
合流点では大きい方の k を採り、遅れた側の鎖全体をその分ずらす。探索も反復も不要。

検証例（現案件）:

```
工程1 生成          t= 700  k=0  →   700 – 2300
工程2 シート取出し   t=5350  k=0  →  5350 – 7600
工程3 W吸盤1        t=7500  k=0  →  7500 – 9000
工程4 L吸盤2        t=8900  k=0  →  8900 – 11600   ← OFF が次サイクル
一生 700 – 11600 ms = 約1.07サイクル
```

「生成3500 / 削除2000」のような逆転も、生成<削除の制約から `削除 k=1 → 12800` と確定する。

## 得られる検査

1. **設定ミスの検出** — 制約グラフに循環があれば解が存在しない。工程割り当ての誤りや、
   変換元と変換先の取り違えを図を描く前に指摘できる
2. **受け渡しの隙間の検出** — 絶対時刻が確定するので、隣り合う保持の重なりを計算できる。
   重なりが無ければ**ワークが落ちる設定**として警告する。
   現案件の重なりは 7500–7600 と 8900–9000 の**各100msしかない**
3. **表示サイクル数の自動決定** — 絶対時刻の最大値をサイクル長で割って切り上げる

## 時間が決まらない区間

コンベア・バケットの搬送時間は設定値ではなく実行結果（置かれた位置・上流の滞留・
ストッパーの状態に依存し、詰まれば何サイクルでも待つ）。

**ただし不定なのは区間の長さだけで、前後の端は必ずタグで確定する。**
合流も最終的には必ずタグで行うため、合流点は確定時刻を持つ。

| 区間 | 時刻 | 図での扱い |
|---|---|---|
| タグ駆動の操作 | 確定 | 実時間の縮尺で描く |
| 搬送 | 長さは不定。両端は確定 | 固定幅の破線区間。縮尺から外す |
| 合流 | タグで起きるので確定 | そのタグで動く複数ワークを線で結ぶ |

横軸は区間ごとに縮尺が変わる「折れた軸」になる。確定区間の中だけが実時間の比較として意味を持つ。

### 合流の役割

合流が無ければ、各ワークの鎖は「何サイクル目に始まったか」が独立に決まり、
レーン同士を並べても意味がない。**合流点で両方の鎖が同じ絶対時刻に合意することで、
初めてワーク間の前後関係が確定する。**

同一タグは「同時に動く」を意味するだけで必ずしも合流ではない（2枚のシートを同時に取る等）。
線で結ぶ判断は自動で行い、それを合流と呼ぶかはラベルの問題として切り分ける。

### 残る不定

**「搬送に何サイクルかかったか」だけ**が最後まで決まらない。
最小解（時刻が矛盾しない最短）を既定とし、マガジンのように滞留する工程では
操作ごとに「＋Nサイクル」を手で指定できるようにする。
合流点があるワーク同士は、その指定が相手のレーンの位置にも波及する。

この方法は**1個のワークを追いかけたときの見え方**を描く。
実行中に同時に流れている複数個体を描くものではない。

## 直接編集

| 操作 | 動作 |
|---|---|
| カードをダブルクリック | ワーク操作の編集ダイアログ（現在の「編集...」と同じ） |
| カードを右クリック | 有効/無効の切替、削除、ワーク操作設定へジャンプ |
| 空セルをダブルクリック | その工程・そのワークで新規操作を追加 |
| カードを別の列へドラッグ | 操作の工程を移し替える（＝担当ユニットの工程を変更） |
| カードを別のレーンへドラッグ | 対象ワークを変更する |

ドラッグの2つは現在のワーク図には無い操作。設定の意味が変わるため実装可否は別途判断。

## 残る検討事項

1. **工程の割り当てをどう入力してもらうか** — サイクル番号の決定に工程順が要るため、
   工程の割り当ては時間軸の前提条件。現案件は工程付きユニットが **0件**。
   工程順の軸で「未分類」列に全部出し、ドラッグで振り分ける導線が要る
2. **工程順の軸と時間軸の切り替え** — 1画面のモード切替を想定
3. **表示するサイクル数の決め方** — 「一生」に動作テーブルの終端まで含めるか、
   削除タグのONまでか。段ボールは削除設定が無いため現案件では動作テーブルしか根拠がない
4. **置き換えで失うもの** — 現在のワーク図の工程フィルタ。時間軸では意味が変わる

## 実装の順序案

1. タグ駆動の鎖だけを対象にした版（搬送・合流は不定区間として置く）
2. 検査（順序が解けない / 受け渡しに隙間がある）だけを先に実装する手もある。
   図が無くてもワーク落ちの原因を潰せる
3. 工程割り当ての入力導線
4. 直接編集
